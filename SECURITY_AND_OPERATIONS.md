# Security and Operations

## Secrets
- Keep secrets in environment variables or a local secrets store.
- Commit only `.env.example` with placeholders.
- Encrypt provider keys at rest if stored in the database.
- Restrict access to secrets to the API process that needs them.
- Never send keys to the browser, logs, analytics or model prompts.
- Rotate keys and support deletion.

## Local network and exposure
- Bind services to localhost by default.
- Do not expose PostgreSQL, Redis, ComfyUI or worker ports publicly.
- Remote access should be added only behind a VPN or authenticated reverse proxy.
- Do not enable public registration in MVP.

## Worker isolation
- Model and render workers must run as non-root where possible.
- Restrict filesystem access to configured input/output directories.
- Never execute arbitrary shell commands supplied in prompts or workflow nodes.
- Use an allowlisted node registry.
- Apply CPU, RAM, GPU and disk quotas where practical.
- Validate media files and enforce size/duration limits.

## Storage and backup
- Use project-scoped storage paths generated by the application.
- Verify file checksums on ingest.
- Separate database backups from media backups.
- Provide export of project manifest and referenced assets.
- Document restore procedures and test them.

## Observability
- Structured logs with request/job/run IDs.
- Do not log secrets or full sensitive media URLs.
- Track queue depth, job duration, worker health, GPU memory and disk space.
- Provide actionable job failure messages.

## Licence governance
Maintain `MODEL_LICENCES.md` (create during Phase 5) with:
- exact model/version,
- official source,
- licence text/link,
- commercial-use interpretation,
- redistribution restrictions,
- attribution requirements,
- date reviewed,
- reviewer/decision.

Do not enable a model for commercial use until its licence has been checked.
